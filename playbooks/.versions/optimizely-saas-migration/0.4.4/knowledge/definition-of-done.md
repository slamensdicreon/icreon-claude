## Reference: Definition of Done

The Director accepts the site against every row at Gate 2, in the live systems (Visual Builder, the editing and delivery hosts, Optimizely Graph); the handover pack's acceptance checklist lists each row with the evidence the engagement already has. Each row needs its evidence, recorded as a document or Activity step. A row without evidence is **pending**, never "passed by code review". Budgets come from the brief; don't set a budget after testing to declare a pass.

| Area                | Required                                                                                                                                      | Evidence                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Brand fidelity      | Approved section order, tokens, imagery, typography, distinctive behaviour                                                                    | Reference comparison at the agreed desktop and mobile sizes |
| Responsive          | No horizontal overflow, clipped controls, unreadable text or broken menus at supported widths                                                 | Screenshots and interaction checks                          |
| Accessibility       | Keyboard operation of menus, search and hero; visible focus; Escape and focus return; labels, alt text, contrast; reduced motion              | Automated report plus a manual journey record               |
| Genuine CMS content | Every agreed editable value comes from a content type property; no mock data hiding missing properties                                        | Property-to-component matrix and sample read-back           |
| Inline editing      | Text, link and image edits persist from live preview in Visual Builder; lists and references edited in the properties panel                   | Visual Builder session evidence                             |
| New component       | Every reusable component is offered as a section or element in Visual Builder, with sensible defaults and a default display template          | A fresh section added to a new experience                   |
| Collections         | Adding, removing and reordering list items changes the display within documented limits                                                       | Before and after version and page evidence                  |
| Independence        | A new experience from a blueprint has its own content; editing it leaves other pages unchanged; shared header and footer reuse is intentional | Distinct keys and a before/after comparison                 |
| Empty states        | Missing content, cleared optional properties, missing media and empty lists stay usable                                                       | Visitor and editor checks                                   |
| Routes              | Home, a child page, a locale route and an unknown route behave correctly on the delivery host                                                 | HTTP status and rendered page                               |
| Navigation          | Every CTA, anchor, social, support and legal link goes to a real, approved destination                                                        | Destination audit; no placeholders                          |
| Search              | Suggestions and select actions work; the real search scope is disclosed                                                                       | Keyboard and destination checks                             |
| Media               | Assets load from Graph with alt text; rights and provenance known; responsive loading and motion policy work                                  | Media inventory and network checks                          |
| Content model       | The content types, display templates and property groups replay from the repository: manifest export committed, dry-run push clean            | Export commit and dry-run record                            |
| Code quality        | Typecheck, lint and the connected build pass on pinned dependencies                                                                           | Command logs tied to the commit                             |
| Editing host        | Correct repository, commit and hostname; Visual Builder renders through it with live preview and refreshes on save                            | Deployment record and Visual Builder session                |
| Publishing          | Every migrated page has a published version per locale, indexed in Graph; visitors see the published version on the delivery host             | Publish record, Graph query, public route check             |
| Security            | No credentials shipped or logged; the single key is the only key in the browser; least privilege; the brief's code-extraction policy followed | Configuration review                                        |
| Performance         | The brief's route, image and JavaScript budgets met on representative devices                                                                 | Measured report against the budget                          |
| Handover            | Editor guide, component limits, release and rollback runbook, ownership, known exclusions                                                     | Approved handover pack                                      |
