## Reference: known Optimizely CMS (SaaS) pitfalls

Two kinds of rows. The first table was **proven on a live instance** (the first homepage
demo, November 2026: SDK and CLI 3.1, REST API v1): each row is something that happened. The
second was gathered from Optimizely's documentation and 2026 release notes and has not been seen
on a build yet: treat those as things to verify. When your evidence says otherwise, trust the
evidence and say so in your result.

Working rules:

- A 2xx means the change was **executed**, not **verified**. Read the content type, the version or
  the Graph item back and compare it with what you intended before you report done.
- After a timeout or an unclear failure on a write, read back first: a create that timed out may
  have succeeded. Never retry a write before you know its state. Don't retry authorization, schema
  or scope failures at all.
- Content types, display templates, property groups and Graph are shared by every application on
  the instance. Create only keys that start with the project's prefix, and never change a type
  that lacks it.
- Publishing is immediate in the CMS, but Graph indexes afterwards. A route check that runs right
  after a publish can be stale: wait for the item to appear in Graph before you judge it.

### Proven on a live instance

| Symptom                                                                                                                                                                                            | Cause                                                                                                                                                                                                                  | What to do                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every content write (`content.create`, `media.upload`, `application.create`, `blueprint.create`) answers 403 "Required access is 'create'", while content types push fine                          | An API key's `api:admin` scope covers the content model; content is governed by the content tree's access rights, and a new key has none. There is no API to grant them                                                | Not something a retry or another path fixes. Raise an **access** blocker: a CMS admin gives the API key (its client ID) Read, Create, Change, Delete and Publish on the Root, in Settings > Set Access Rights. `verify-access` asks for this before Gate 1                                                              |
| `POST /applications` answers 400 "must start with a non-numerical character and only contain alphanumerical characters or underscore"                                                              | An application key takes no dashes or spaces                                                                                                                                                                           | The key is the Director's name with underscores (`Acme Website` is `Acme_Website`): the tool server derives it; paths use the key (`/content/Acme_Website`)                                                                                                                                                             |
| A blueprint or content item is refused: "only supports keys formatted as a GUID"                                                                                                                   | Content and blueprint keys are 32 hex digits                                                                                                                                                                           | Don't invent keys: the tool server derives one from the item's path, so the same path always reaches the same item                                                                                                                                                                                                      |
| A component the team never styled renders with another team's display settings, or its own default template is ignored                                                                             | The instance already holds a `baseType: '_component'` template marked default (someone pushed the starter's samples); it applies to every component without a default of its own                                       | Give every section-enabled content type its own display template with `contentType: '<its key>'` and `isDefault: true`. `editor.element-enabled` checks this                                                                                                                                                            |
| A push would create an application, a start page or locales nobody asked for                                                                                                                       | `optimizely.config.mjs` lists `applications`, `content` or `locale`: a full `config push` creates them instance-wide                                                                                                   | Keep only `components` in the config. The application and its content are made through `optimizely-cms`; `exec.optimizely-cli` pushes with `--only` the keys it checked, which leaves applications and locales alone                                                                                                    |
| Bringing component branches together stops on a conflict in the file that lists every component, or the first content model check names `AboutExperience`, `Tile` and other keys nobody wrote      | The official starter lists every component by hand in `layout.tsx`, so each branch adds a line in the same place; and it ships sample components, two applications and property groups, none with the project's prefix | Our starter has no samples and generates its registry: a component is one folder, `<Name>.model.ts` and `<Name>.tsx`, and the component file exports `resolver` (the content type keys it renders). `src/cms/registry.generated.ts` is written by `build`, `type-check` and `dev`, is not committed and is never edited |
| Every build is red before anything was changed: "Missing script: type-check"                                                                                                                       | The official starter has no `type-check` script; ours does (route types, then `tsc`)                                                                                                                                   | Never remove the app's `type-check` and `generate-registry` scripts. A stale `.next/types` after a route moved is cleared by `type-check` itself (`next typegen`)                                                                                                                                                       |
| The CLI fails on a component file, or pulls React and CSS into the manifest build                                                                                                                  | The CLI bundles every file the `components` glob matches (esbuild, Node)                                                                                                                                               | Keep the content model in `*.model.ts` files with no React, CSS or `next/*` imports; the component imports its model. Glob: `./src/components/**/*.model.ts`                                                                                                                                                            |
| The start page is not at `/` in Graph, and `getContentByPath('/')` finds nothing                                                                                                                   | Routes start with the locale: an application's start page is `/en/`                                                                                                                                                    | The head reads `/<default locale>/…` for a path without one, so `/` shows the start page                                                                                                                                                                                                                                |
| A route query returns another site's page, or two start pages                                                                                                                                      | One Graph index holds every application on the instance; several have `/en/`                                                                                                                                           | Always narrow by host: `_metadata.url.base` is the application's primary host with its scheme (`https://acme.vercel.app`), null for an application with no host. `graph.routes` does this                                                                                                                               |
| An image upload is refused or lands as a plain file                                                                                                                                                | The image content type (`ImageMedia`) takes jpg, png, gif, svg, webp, bmp, ico, tiff, heif: not AVIF                                                                                                                   | Fetch the image as WebP, PNG or JPEG; `media.upload` refuses AVIF with this advice. Alt text is the item's `AltText` property                                                                                                                                                                                           |
| Visual Builder's frame shows a Vercel login                                                                                                                                                        | Vercel Authentication is on for the hosting project                                                                                                                                                                    | It must be off: the CMS loads `/preview` in a frame. `head.preview-route` checks the route answers without a login                                                                                                                                                                                                      |
| The head crashes at start on the host with a read-only file system                                                                                                                                 | The official starter's `src/instrumentation.ts` writes `otel-output.log` to the working directory                                                                                                                      | Our starter has no such file (nor the OpenTelemetry packages): never add it back                                                                                                                                                                                                                                        |
| `next build` leaves `AGENTS.md` and `CLAUDE.md` in the app                                                                                                                                         | Next.js 16 generates agent rules                                                                                                                                                                                       | Keep `agentRules: false` in `next.config.ts`, as our starter sets it                                                                                                                                                                                                                                                    |
| A list of cards or links is refused: "Could not read value as 'component'. Expected object."                                                                                                       | An item of a list of inline components was sent with its type (`{ contentType, properties }`)                                                                                                                          | An item is its properties only: `{ properties: { … } }`. The list's content type already says what each item is. A section of a composition is different: its `component` does name its `contentType`                                                                                                                   |
| Every image on the page renders with an empty `alt`, though the images have alt text in the CMS                                                                                                    | The SDK asks Graph for a referenced image's fields only for media types the head has registered; unregistered, a reference comes back as a key and a URL                                                               | Keep the CMS's own image type registered in the head, as our starter does in `src/cms/media.ts` (`key: 'ImageMedia'`, `baseType: '_image'`, `properties: { AltText }`), in a file the CLI's `components` glob does not match: it is the instance's type and must never be pushed                                        |
| `blueprint.create` answers 403 "You do not have access rights to create blueprints" though pages publish fine                                                                                      | Blueprints have a right of their own, separate from content rights                                                                                                                                                     | Not retryable. An editor saves a finished page as a blueprint in Visual Builder, or an admin grants the key that right; say which in your result                                                                                                                                                                        |
| A read straight after a create answers 404                                                                                                                                                         | The API is briefly behind its own writes                                                                                                                                                                               | Take the version from the create's own answer (`Prefer: return=representation`); if you must read, wait a moment and read once more before concluding anything                                                                                                                                                          |
| You need to see a draft on the head, or check the editing frame, without a person in the CMS                                                                                                       | Preview tokens come from the CMS                                                                                                                                                                                       | `content.previews` returns the address Visual Builder opens (the head's preview route with a token good for a few minutes). In the editing frame (`ctx=edit`) every editable property carries `data-epi-edit` and every section `data-epi-block-id`: `head.preview-route` counts them                                   |
| An editor opens a page in Visual Builder and it is blank: no sections, no header, nothing to edit, though the live page is complete                                                                | The page has an older draft beside its published version (the empty start page an application is created with, never filled). Visual Builder opens the draft                                                           | Never leave a second draft: a draft is changed in place (the tool server does this), and only a published item gets a new one. If it happened, delete the stale draft version; check with `content.read` that the page's one version is the one with the sections                                                       |
| `hostname.add` is refused: "Headless applications only allow Primary, Preview, and Media hosts", or "Only one preview host is allowed"                                                             | An application has one primary host and one preview host; there is no "edit" host type                                                                                                                                 | Primary is the production address (where visitors get the site, and what Graph's routes are on); preview is the editing address (where Visual Builder opens pages). `hostname.add` takes `use: primary` or `use: preview`, primary first; a new one replaces the one before                                             |
| An image's alt text can't be changed: "Media content must be provided for media content types"                                                                                                     | A new version of a media item must name its stored file                                                                                                                                                                | Send the version with `media: { key }` copied from the item's latest version, the new `AltText`, and publish it                                                                                                                                                                                                         |
| A probe for "can this key create content?" always answers 400                                                                                                                                      | The API validates the body before it checks access                                                                                                                                                                     | There is no write-free probe; the first real write tells. Don't spend calls looking for one                                                                                                                                                                                                                             |
| Every push of content types fails (`InvalidModel`: "The field 'required' does not exist on type 'ContentTypeProperty'"), though the build and the dry run are green                                | A model file names a property option `required` or `localized`. The SDK and the CMS call them `isRequired` and `isLocalized`; the SDK's types let the wrong name through, and so does the CLI's dry run                | Rename them in every `*.model.ts`. The sandbox's dry run now stops on them and names the properties. It is never the API key: a key that can't push fails the dry run too, which fetches a token                                                                                                                        |
| A display template is refused: "The choices object contains a field whose name '3' does not meet the minimum length requirement of 2 characters"; the content types of the same push were imported | A display setting's choice key is one character                                                                                                                                                                        | Give every choice key two characters or more (`cols3`) and read the new key in the component. The rest of that push did land: push again once it is fixed                                                                                                                                                               |
| `application.create` answers 400: "Property '…' is required" for the start page                                                                                                                    | The page type has required properties, and the application's start page is made as an empty draft, before any content or shared block exists                                                                           | Page types an application starts on have no required property, and a reference to a shared block (header, footer) is never required. The Blueprint check fails on it; fix the model file and push again                                                                                                                 |
| A push is refused: "Property '…' changes 'isRequired' from 'true' to 'false'. The change could result in data loss"                                                                                | The CMS treats dropping a requirement as possible data loss, though no value can be lost by it                                                                                                                         | Push again: the sandbox's push applies this one change by itself (those types only, with the override) when it is all the CMS objects to, and says which properties it made optional. A property removed or retyped is still never forced                                                                               |

### From the documentation, not yet seen on a build

| Symptom                                                                                                             | Likely cause                                                                                                                                                                           | What to do                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Calls to `/_cms/preview3/...` fail or are refused                                                                   | Preview3 was retired on 1 August 2026                                                                                                                                                  | Use CMS REST API v1 on `https://api.cms.optimizely.com/v1/...` with a bearer token from `/oauth/token`. Status changes are no longer a field on create                                                                                                                                                                                                                                                                                          |
| `config push` stops before uploading anything                                                                       | A `content` or `contentReference` property has no `allowedTypes`, `restrictedTypes` or `contentType`                                                                                   | Every such property (array items included) needs exactly one constraint. Run `config push --dryRun` first; the CLI lists every violation                                                                                                                                                                                                                                                                                                        |
| A property disappeared or its type changed after a push, and content with it was lost                               | `config push --force`                                                                                                                                                                  | Never push with `--force`. Without it the CMS rejects changes that lose data; report the rejection as a decision instead                                                                                                                                                                                                                                                                                                                        |
| A type you removed from code is still in the CMS                                                                    | `config push` never deletes                                                                                                                                                            | Deleting is a separate, confirmed step (`config delete`, or the Director in the UI); a type with content can't be deleted at all                                                                                                                                                                                                                                                                                                                |
| Two projects' types collide, or a push changes another site's type                                                  | Type keys are instance-wide                                                                                                                                                            | Prefix every key with the project's prefix; use `--only <keys>` to push just this project's types                                                                                                                                                                                                                                                                                                                                               |
| A component can't be added in Visual Builder                                                                        | Missing `compositionBehaviors`                                                                                                                                                         | `elementEnabled` for a block inside a column, `sectionEnabled` for a block that is a whole section. Register it with `initContentTypeRegistry` too, or the SDK fetches none of its properties                                                                                                                                                                                                                                                   |
| A Graph query for an item by key returns nothing                                                                    | The key has hyphens                                                                                                                                                                    | Keys are UUIDs written as 32 hex characters without hyphens in Graph; strip them before querying                                                                                                                                                                                                                                                                                                                                                |
| Publishing a second version in the same locale fails or overwrites                                                  | One published version per locale                                                                                                                                                       | Create a new version and publish it; the previous one becomes `previouslyPublished`, which can't be edited or republished                                                                                                                                                                                                                                                                                                                       |
| A draft is invisible to the head                                                                                    | The single key reads published content only                                                                                                                                            | Drafts need a preview token (from the preview URL, valid five minutes, sent as `Authorization: Bearer`) or an HMAC-signed request with the app key and secret                                                                                                                                                                                                                                                                                   |
| The preview frame in Visual Builder is blank                                                                        | The hostname isn't on the application, `/preview` doesn't load `communicationinjector.js`, or CSP forbids framing                                                                      | Add the exact host (with port) under Settings → Applications → Hostnames; load `<CMS URL>/util/javascript/communicationinjector.js` on `/preview`; allow `frame-ancestors` and `script-src` for the CMS host                                                                                                                                                                                                                                    |
| Edits save but the preview doesn't refresh                                                                          | No `optimizely:cms:contentSaved` listener                                                                                                                                              | Use `NextPreviewComponent` (or `PreviewComponent`), which listens for the event and re-renders with the new token                                                                                                                                                                                                                                                                                                                               |
| A component can't be selected in Visual Builder                                                                     | A custom `ComponentWrapper` without preview attributes                                                                                                                                 | Spread `pa(node)` from `getPreviewUtils` onto the wrapper; a custom wrapper replaces the default one, attributes included                                                                                                                                                                                                                                                                                                                       |
| Display settings read as strings, or a tagged variant never renders                                                 | Graph returns settings as strings; `initDisplayTemplateRegistry` replaces the list on every call                                                                                       | Let the SDK convert booleans (`displaySettings?.flag` works); register every template in one call                                                                                                                                                                                                                                                                                                                                               |
| Rich text renders as `[object Object]` or raw JSON                                                                  | SDK 3 returns rich text as JSON unless told otherwise                                                                                                                                  | Render it with the SDK's `RichText` component, or set `fragment.richTextFormat`                                                                                                                                                                                                                                                                                                                                                                 |
| A published page never appears on the delivery host                                                                 | Graph not indexed yet, or the application has no route for it                                                                                                                          | Check the item in Graph (`_metadata.url.default`), then the application's start page and the item's container chain; run "Optimizely Graph Full Synchronization" under Settings → Scheduled jobs only as a last resort                                                                                                                                                                                                                          |
| An item exceeds Graph's limit and stops indexing                                                                    | Items over 29 MB                                                                                                                                                                       | Split large compositions; keep media as assets, not inline                                                                                                                                                                                                                                                                                                                                                                                      |
| A newly created item has no display templates applied                                                               | Created through the API before August 2026 fixes, or no default template exists                                                                                                        | Mark one template per target `isDefault: true`; read the composition back and name the template on each node (`displayTemplate` in `composition.write`) where it is missing                                                                                                                                                                                                                                                                     |
| The CLI logs in to the wrong place                                                                                  | `--host` or `OPTIMIZELY_CMS_API_URL` set to an instance URL                                                                                                                            | Leave the API URL as the gateway; an instance URL makes the CLI call `<url>/_cms/v1`, which only the gateway form supports for keys created in the UI                                                                                                                                                                                                                                                                                           |
| The source site answers HTTP 401/403 to every browser read (snapshot, markup, styles), though some plain reads work | The site's bot protection refuses automated browsers. It is the site's choice, not our access: retrying, slowing down or another tool won't change it, and we never try to get past it | Ask the Director once (needs_decision): they save the pages the work needs from their own browser (Chrome or Edge: Save page as, "Webpage, Single File" .mhtml) and attach them, or the project uses another site. An attached `.mhtml` is that saved page: every browser read of its URL answers from it, marked "from the Director's saved copy". Never media.upload the .mhtml itself; images inside it come out through browser.fetch.asset |
