## Reference: known SitecoreAI pitfalls

Observed on earlier SitecoreAI builds (the BLDR / New Brand site, and Ansco Associates on a shared
tenant). They are observations, not platform guarantees: if your evidence says otherwise, trust the
evidence and say so in your result.

Working rules:

- A successful call means the change was **executed**, not that it is **verified**. Read the item,
  layout or route back and compare it with what you intended before you report done.
- After a timeout or an unclear failure on a write, read back first: a create that timed out may have
  succeeded. Never retry a write before you know its state. Don't retry authorization, schema or
  scope failures at all.
- Find existing items by path and template before you create anything. Preserve fields you don't own.
- Publishing and deploys are tracked jobs: record the job id, wait for its final status, then check
  the result on Experience Edge or the host.

| Symptom                                                                                       | Likely cause                                                                                                                                                                       | What to do                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A page exists and publishes, but its URL is a 404                                             | The page is a sibling of Home, not under the site's start item                                                                                                                     | Create routes beneath Home. Test the route through the layout query, not just the item                                                                                                                                                                 |
| A component is on the page but its datasource doesn't resolve                                 | Non-canonical datasource ID                                                                                                                                                        | Use canonical, hyphenated, braced GUIDs in presentation. Check `isContentResolved` after publishing                                                                                                                                                    |
| Publish errors or an empty rendered component                                                 | Hand-written presentation XML missing attributes                                                                                                                                   | Write full `id`, `ph`, `uid`, `ds`, device `id` and layout `l` attributes; read the saved presentation back                                                                                                                                            |
| Header or footer missing although the partial design exists                                   | Missing partial-design signature, site-level placeholder setting, or unpublished rendering definition                                                                              | Trace wrapper → placeholder → rendering definition → datasource. Publish the rendering definitions explicitly: publishing related items doesn't reliably include them                                                                                  |
| A page or partial design lacks expected fields                                                | Created from a generated folder template                                                                                                                                           | Use the real design-item template; check inheritance and insert options first                                                                                                                                                                          |
| Some sections render blank with no error                                                      | Edge GraphQL query complexity limit                                                                                                                                                | Check the GraphQL `errors`, not only HTTP 200. Use `fields(ownFields: true) { name jsonValue }` on wide items. Keep each component inside the Blueprint's query budget                                                                                 |
| Nested navigation fails as it grows                                                           | Children × grandchildren × fields cost                                                                                                                                             | Bound collections (the earlier build held 4 groups × 5 links) and tell editors the limit                                                                                                                                                               |
| A newly added component shows "No Text in Field"                                              | Blank own values on the branch root override standard values                                                                                                                       | Populate the branch `$name` root as well as standard values; test with a genuinely new datasource                                                                                                                                                      |
| Updating a field says the language version is missing                                         | The item has no version in that language                                                                                                                                           | Add the version through the API (with approval) before updating; never invent versions across languages                                                                                                                                                |
| Media disappears after a clean sync                                                           | Media outside the module's includes, or no blob in serialization                                                                                                                   | Keep media under the project's media folder and check the serialized payload, not just the reference                                                                                                                                                   |
| A template field deletion fails, or succeeds but the field remains                            | Inconsistent field deletion                                                                                                                                                        | Re-read after each attempt and stop; report the stale field rather than looping                                                                                                                                                                        |
| A component vanishes after a build                                                            | The generated component map was hand-edited, or names differ                                                                                                                       | Fix the source export and regenerate with the Content SDK CLI; the map key must equal the rendering's `componentName`                                                                                                                                  |
| The wrong language or site resolves                                                           | Proxy order or multisite config                                                                                                                                                    | Keep the locale proxy before the multisite proxy; test routes in each language, not only `/`                                                                                                                                                           |
| The editing host can't find a workspace package                                               | Build context excludes sibling packages                                                                                                                                            | Build from the repository root with filtered scripts; keep the lockfile and package manager pinned                                                                                                                                                     |
| The editing host stays broken after reconnecting                                              | Wrong host key, or only one of the two targets reconnected                                                                                                                         | The rendering host key must be identical in `xmcloud.build.json` and the host record. Never create a suffixed duplicate host                                                                                                                           |
| Preview content says "No sitecore context"                                                    | Wrong context or header spelling                                                                                                                                                   | Confirm the preview context is the intended one; direct queries use `sitecoreContextId` (camelCase)                                                                                                                                                    |
| A menu opens then immediately closes                                                          | Focus and click handlers racing                                                                                                                                                    | Review them together; test mouse, keyboard, Escape and editor-chrome focus                                                                                                                                                                             |
| Page builder greys out the project's components                                               | The site renders through another site's editing host (the environment's Default), whose code lacks them                                                                            | Each site gets its own rendering host (`rendering-host.set`) pointing at the integration build; components reach it only once integrated                                                                                                               |
| A setting the site needs "has no field"                                                       | Field names differ from their labels (`RenderingHost` is shown as "Predefined application rendering host")                                                                         | Read the item's field list and match the field name, not the label                                                                                                                                                                                     |
| Insert options or layout "don't apply" though they read back                                  | Set on the template item itself, which Sitecore ignores                                                                                                                            | Set `__Masters` and `__Renderings` on `<template>/__Standard Values`, and read them back from there                                                                                                                                                    |
| A standard field (`__Masters`, `__Renderings`) reads as missing                               | The item's field list is paged; standard fields fall past the first page                                                                                                           | Read named fields (`item.read` with `fields`); don't conclude a field is empty from the full list                                                                                                                                                      |
| A layout write "mismatches" on read-back                                                      | Sitecore rewrites layout XML (braces, case, attributes)                                                                                                                            | Compare renderings, placeholders and datasources, not the XML text                                                                                                                                                                                     |
| A name differs from the Blueprint                                                             | Created under another name                                                                                                                                                         | Rename with `item.rename` (the ID, mappings and references stay); never delete and recreate                                                                                                                                                            |
| A rendering is "not offered" though it was added                                              | Duplicate renderings of the same name, or the ID added to the wrong group                                                                                                          | Keep one rendering per name; check the ID in `<site>/Presentation/Available Renderings/<group>` → `Renderings`                                                                                                                                         |
| Templates the Blueprint merged "are missing"                                                  | A merged template has no item of its own                                                                                                                                           | Check the merge target exists instead; record the merge in the report                                                                                                                                                                                  |
| A media file won't download or upload                                                         | Media lives on a CDN or in the repository, not the source host                                                                                                                     | Download with `fetch.asset` (it accepts hosts the Blueprint points at), then upload its `ref`; never ask for URLs the Blueprint or pages give                                                                                                          |
| Page copy is cut off                                                                          | Crawl excerpts are capped                                                                                                                                                          | Use the snapshot's `content` (whole text) or the source repository's content files; never invent copy                                                                                                                                                  |
| A datasource location points at content that doesn't exist yet                                | The content is a later phase's work                                                                                                                                                | Point at the folder that exists; leave the item to the content phase and say so                                                                                                                                                                        |
| Work waits on something another task makes                                                    | Ordering                                                                                                                                                                           | Wait on that task (`waiting`); send finished work back to its owner (`sendBack`); never wait on a later phase, never ask the Director to route it                                                                                                      |
| Page builder opens a migrated page empty, though its items exist                              | The layout lists renderings without their rendering IDs, or sits only in the page's final layout                                                                                   | Place components with `layout.compose` `renderings` (rendering, placeholder, datasource); never hand-write layout XML. Check in Page builder                                                                                                           |
| Layout Details lists no controls, Page builder shows a red bar                                | The layout's IDs are 32 bare hex digits, as the authoring API returns them; Sitecore reads only `{8-4-4-4-12}`                                                                     | Use `layout.compose`, which writes IDs in Sitecore's form and refuses IDs no item has; `structural.layouts` catches the rest                                                                                                                           |
| Page builder shows JSON like `{"datasource":…,"fieldId":…}` above every field                 | The head's `Layout.tsx` no longer renders `<Scripts />` / `<EditingScripts />`, so the field markers never become editing chrome                                                   | Restore `<Scripts />` in `src/Layout.tsx` as the starter has it; components never edit the app shell. `head.editing-scripts` checks it                                                                                                                 |
| Pages answer 500; Page builder shows "A rendering error occurred in component …" (React #441) | A server component calls `useSitecore()` or another hook; the build stays green, the render fails                                                                                  | Start that component's file with `'use client'`; `head.pages-render` loads every page on the editing host                                                                                                                                              |
| The header or footer shows "choose a datasource" or nothing, though it's placed               | Its code reads `fields.data.datasource` (GraphQL), and its rendering has no Component Query                                                                                        | Set a Component Query on the rendering returning the fields and children the code reads, aliased to its names                                                                                                                                          |
| Cards, counters, FAQ questions or jobs don't show; the component shows only its heading       | The component reads `fields.data.datasource.children`, but its rendering has no Component Query (or the datasource has no child items)                                             | Write the query as `<Name>.graphql` with the component; set it on the rendering's `ComponentQuery`; create every child item. `structural.component-queries` and `parity.render` check both                                                             |
| Every section runs full width with no background; pages look nothing like the source          | Components don't render inside the design system's `Section` (container, padding, band)                                                                                            | Wrap each component in `ui/Section` with `tone` from its rendering parameters; set `tone` per placement to match the source. `head.sections` checks it                                                                                                 |
| A page passes its checks but looks unlike the source                                          | Sections mapped to the nearest component or default variant, text split across components, items missing                                                                           | Map the source page section by section (component, variant, tone, items) before building; `parity.render` compares the rendered page with the source                                                                                                   |
| A list component's heading or items go blank once its Component Query is set                  | With a query, Sitecore sends only `fields.data`; code reading `fields.heading` or `item.fields.title` finds nothing                                                                | Read fields from `fields.data.datasource.<name>.jsonValue` and items from `children.results[i].<name>.jsonValue` (accept both shapes)                                                                                                                  |
| The header and footer are wired but `headless-header` / `headless-footer` render empty        | Partial designs made from the MVC SXA template (`Experience Accelerator/…/Partial Design`), or `TemplatesMapping` written as `{template}={design}`: Sitecore ignores both silently | Create partial designs from `JSS Experience Accelerator/Presentation/Partial Design`; map templates with `page-designs.map` (Sitecore's `configurePageDesigns`). Check the layout query lists the renderings inside the header and footer placeholders |
| A component's variant (`FieldNames`) has no effect                                            | The variant isn't an item, or the parameter holds the variant's name                                                                                                               | Create `<site>/Presentation/Headless Variants/<Component>/<Export>` for each code export used, and set `FieldNames` to that item's ID; the layout service sends its name                                                                               |
| The header gets no data (`isContentResolved: false`); a 50-item list renders empty            | Query complexity: a nested `children(first: N)`, or several aliased fields on many children                                                                                        | Nested children without `first` (default page 10); for long lists select `fields(ownFields: true) { name jsonValue }` per child and read that shape in the head (`ui/fields` `itemFields`)                                                             |
| Sitecore changes don't show on the editing host; images break a while after each deploy       | Pages render once per deployment and stay cached: edits never appear, and the signed CM media links in the cached HTML expire (they redirect to the Sitecore login)                | The editing host renders per request: `SITECORE_RENDER_ON_REQUEST=true` on the hosting project, `await connection()` in the page route when set, and no `generateStaticParams` export then. Never redeploy to refresh content                          |
| Every page answers 500 after making the editing host render per request                       | The page route still exports `generateStaticParams`, so it is static and a request-time render fails ("changed from static to dynamic at runtime")                                 | Export `generateStaticParams` only when `SITECORE_RENDER_ON_REQUEST` is unset; the build lists the route as `ƒ`, not `●`                                                                                                                               |
| A file download shows its label but no button                                                 | The File field holds General Link XML (`<link linktype="media" …>`); the layout service returns `null`                                                                             | Write File fields as `<file mediaid="{…}" />`                                                                                                                                                                                                          |
| Headings or buttons vanish on a red or navy band                                              | Red `.primary` headings and red buttons on a `bg-primary` band                                                                                                                     | The design system lets `.primary` inherit on coloured bands and outlines buttons there, as the source does                                                                                                                                             |

Never: reset or clear a tenant or Experience Edge to recover one component; push serialization
into a shared collection; change items outside the project's own paths.
| Pages pass text parity (98–100%) but look nothing like the source | Each section was rebuilt from its copy, not its layout: wrong variant, column split, image side, band or list style | Build from the inventory's `sections` (the live page's layout per section), one variant per distinct layout; `parity.visual` compares screenshots and lists each difference |
| The new site copies the source repository faithfully and still differs from the live site | The client's code rebuild isn't the live site (Ansco's dropped the footer's `order-lg-*` columns, the contact page's layout) | The live site is the truth. Inventory and compare against it; use the repository only to find copy and assets |
| A new datasource item shows "Section heading" (or another default) | Fields left unset show the template's standard value | Create items with every field set, empty ones as an empty string; `parity.render` fails pages showing placeholder copy |
| Rich-text bullets and numbers are missing | The starter's Tailwind preflight sets `list-style: none` on every list | The design system restores authored lists (`.component ul:not([class])`, `ol`) and the source's list styles (check marks) |
| Text parity drops after making a section conditional (a form's address, a carousel) | The hidden content was left out of the markup, so its copy isn't on the page | Keep it in the page, hidden (`hidden`, plus `disabled` for form fields), as the source does |
| Screenshots miss content near the top of the page | A cookie or chat banner fixed mid-screen covers it in the capture | `browser.screenshot` scrolls the page and hides mid-screen fixed overlays before capturing; when comparing by eye, dismiss the banner |
| The registrar asks who creates the header's navigation or footer item, and partial designs wait on it | Each role thought the other owned the header's and footer's datasources | The Layout Engineer creates them in `partial-designs`; the registrar stops at templates, rendering, variants and Component Query |
| A task blocks "not connected" for a tool it never calls (Experience Enabler and Page builder) | The live guard checks every server the role is granted | Give the template `uses:` the servers its tasks need; only those must be connected |
| The production integration hits source conflicts on many port branches | It brought in branches never integrated: cancelled components, duplicates (`port-header` beside `port-site-header`), ones merged into another component as variants | Integrate only branches already in `launchworks/integration`; the editing host's code is the reference |
| The release deployed the starter: production runs the build repository's first commit | The production deploy builds `main`, and nothing moved `main` to the reviewed integration commit | `build-repo.branch.promote` with the reviewed commit before `hosting.deploy.production`; `deploy.commit-matches` checks production against the integration head |
